# Morpheus query-splitter synthetic training queries

Generated by `data_generation/synthetic_queries` (profile `full`, seed 42). No LLM / API calls were used:
labels come from repo label constants, deterministic template metadata, controlled rule-based transformations and agent-authored
phrase banks. Nothing here was used to train a model.

## Files
| file | content |
|---|---|
| `train.jsonl` / `validation.jsonl` / `test.jsonl` | 80/10/10 split, **semantic groups never cross splits** (rows: 19975 / 2514 / 2511) |
| `all_samples.jsonl` | every final row incl. the full semantic spec and per-segment provenance used for validation |
| `rejected.jsonl` | rows rejected at map/reduce time with reason codes (includes exact duplicates) |
| `near_duplicates.jsonl` | near-duplicates removed (normalised-equal, or token-Jaccard >= 0.9 across groups) |
| `allowed_labels.json` | NER tags, listing type/status/amenity vocabularies and the repo files they were read from |
| `statistics.json`, `validation_report.json`, `generation_manifest.json` | distribution stats, validation + stop-condition results, provenance |

## Record schema (split files)
`query`, `tokens`, `ner_tags` (BIO over the repo `ALLOWED_LABELS`), `listing_type_annotation`, `listing_status_annotation`,
`amenities_annotation` (lists of repo labels), `min_max_annotation` (dict keyed by lower-case numeric NER entity, value `[min, max]`,
e.g. `{"beds": [3, 3], "price": [null, 500000]}`; keys: beds, baths, price, sqft, lotsqft, lotacre, homeage, hoa, garage, story),
`min_max_spans` (one row per numeric NER span: `entity`, `ner_subquery`, `min_max` as `[min, max]` - the unit `min_max_model.py` trains
on, where `ner_subquery` is the input and `[min, max]` the target; the repo's `--annotation_format dict` is `{"min", "max"}` of that pair), plus metadata
(`semantic_group_id`, `spec_id`, `template_family`, `variant_style`, `transforms`, `domain`, `edge_case`, `split`).
`all_samples.jsonl` additionally has `spec`, `segments`, `pattern`.

## Labeling conventions (taken from the repo labeling prompts; please review)
* min/max: `3 beds` -> `[3, 3]`; `3+ / at least / more than` -> `[3, null]`; `under / up to / max` -> `[null, n]`; ranges -> `[lo, hi]`;
  `no hoa` and `new construction` -> `[0, 0]`; bare/low `hoa` mention -> `[null, null]`; bare `acres` -> `[1, null]`; bare `garage` -> `[1, 1]`;
  `garages` -> `[1, null]`; price/hoa in dollars, lot in acres or sqft, home age in years.
* listing type: duplex/triplex always also `multi_family_home`; house/home -> `single_family_home`; studio/loft -> condo group;
  `land` only for undeveloped land; a phrase with no type word gets no type label.
* listing status: explicit wording wins; otherwise `apartment` implies `for_rent`; with a non-apartment type a sale-sized price
  (>= $30,000) implies `for_sale` and a rent-sized price (<= $15,000) implies `for_rent`.
* amenities: labels come from the repo's human-reviewed phrase variations (ambiguous / conflicting phrases removed). A numeric HOA fee has
  no amenity label; `no hoa` -> `no_hoa`, `hoa` -> `hoa`, `low hoa` -> `low_hoa`; `new construction` is tagged `HOMEAGE` in NER and
  `new_construction` in amenities. Negated amenities ("no pool") keep an `AMENITY` span but get no amenity label.
* NER: proximity wording (`near`, `close to`, `within 10 miles of`) is part of the `LOCATION` span (repo prompt); `for rent` is a
  `LISTINGSTATUS` span; `open house` is an amenity (the repo marks `open_house` as an amenity label).

## Size and quality
* rows: 25000 unique queries from 4183 specifications / 4134 semantic groups
* template families used: 75; distinct NER skeletons: 9809
  (most common skeleton = 1.2% of rows)
* tokenizer: `spacy` (matches `spacy.blank("en")` used by the repo's labeling code)
* validation report: see `validation_report.json` (status: **complete**)

## Reproduce
```
cd projects/listing_sequences/user_query_classification/data_generation
python -m synthetic_queries.orchestrator run --profile full
```
The job is shard-based and resumable (`work/` holds spec shards, mapper shards, reducer shards and completion markers).
